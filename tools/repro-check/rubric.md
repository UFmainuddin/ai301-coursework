# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| environment-recorded | The repro report's environment statement (software version, OS, install/config context), read against the version or platform the issue targets (`references/evidence-guide.md` § Environment) | The report states the version, OS, and relevant install/config context it actually ran against. If that differs from what the issue reports, the report says so explicitly. Stating no environment at all, or matching the issue's version/OS only by silence, fails this check. | required |
| steps-followable | The repro report's reproduction steps (commands, inputs, config), read for whether a stranger with only the report could carry them out (`references/evidence-guide.md` § Steps) | Every step is either shown verbatim (an exact command, an exact input) or described precisely enough (exact field names, exact values, exact flags) that a stranger could reconstruct the identical input or action without guessing. No step depends on a resource only the author has (a private repo, an unshared config file) and no step is a vague, unstated setup action ("configure the project", "set it up the usual way"). | required |
| artifact-matches-issue-behavior | The output, log, or artifact shown in the report, read character-for-character against the exact behavior the issue describes (error type, exit behavior, panic signature, or symptom), not a similar-looking but different outcome (`references/evidence-guide.md` § Behavior shown) | The artifact shown demonstrates the same behavior the issue reports (same error class, same exit/crash behavior, same symptom) — judged by what the artifact itself contains, never by the report's length, formatting, or confidence. An honest, evidenced cannot-reproduce (the artifact shows a different, non-matching result and the report says so) also passes. An artifact that shows a different behavior than the issue describes, silently narrated as a match, fails. A claimed reproduction with no artifact shown at all fails. | required |
| honest-outcome | The report's stated conclusion (reproduced / could not reproduce / root cause), read against what the shown artifacts actually demonstrate (`references/evidence-guide.md` § Honesty) | The stated conclusion matches exactly what the artifacts show. An explicit "could not reproduce" that names what was tried and what differed is a full pass. A conclusion (diagnosis, confirmation, certainty) asserted beyond what the shown evidence supports — or asserted with no evidence shown — fails. | required |
| claim-specific-and-honest | The claim comment, read against the issue's specific content and against generic boilerplate (`references/evidence-guide.md` § Comms) | The claim comment names something specific to this issue (the symptom, the file, or the mechanism) and promises only investigation/a report, not a fix, a timeline, or a guarantee. A comment that is interchangeable with any issue ("I'd like to work on this", a bare "+1"), or that promises a fix or a date, fails. | required |
| disclosure-compliant | The repo-facts block's stated AI-contribution/disclosure policy, read against whether the claim and repro comments disclose AI assistance (`references/evidence-guide.md` § Comms) | If the repo's stated policy requires disclosing AI assistance, the comments disclose it. If the policy is silent or permissive with no disclosure requirement, this check passes automatically. A comment that omits required disclosure fails, regardless of how good the rest of the package is. | required |

## Verdict rule

Accept only if every required check grades `pass`. Any required check graded `fail` or `unclear` holds the package (verdict `reject`). There are no `preferred` checks in this rubric — every family the lecture named gates the verdict, because a reproduction that is weak in any one of them (unrecorded environment, unfollowable steps, a mismatched artifact, an overclaimed outcome, a boilerplate or non-specific claim, or missing required disclosure) is not ready to post. `unclear` on any required check is treated as `fail`: evidence I cannot verify is not evidence that it's ready.

On a claim-only draft (live mode, early in the week), only `claim-specific-and-honest` and `disclosure-compliant` are evaluated against the verdict; the other four checks report `unclear` / `not yet applicable: claim-only draft` per `SKILL.md` and do not count toward that verdict.
